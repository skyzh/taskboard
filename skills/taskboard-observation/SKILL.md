# Run an observation review

Keep one owned goal per outcome. Record the subject, baseline, evidence sources, review cadence, and the decision the evidence should inform. Use a standing goal for ongoing upkeep. For a bounded run, set an end date and criteria for continuing, changing course, or stopping. Keep existing incident cadences and milestone deadlines.

Use the existing goal review schedule. At each due review, read the last outcome and applicable decisions, inspect the agreed signals, and record one dated result on the same goal. Record what changed, what stayed steady, what could not be verified, and the next action. Link evidence. If a normal work pass already recorded the day's outcome, count it and avoid duplicate reminders and reports.

Choose evidence suited to the goal:

- For an SOP, sample actual use and stage a narrow correction when evidence shows recurring friction.
- For a release, compare with the baseline against the agreed keep, fix, or rollback criteria.
- For exploration, record what was tried, the time or compute used, and the strongest evidence. Apply the agreed budget and stop criteria before extending the run.

Ask the human through a linked Taskboard decision when their answer changes the next action. Include the options, consequences, timing, and evidence. Preserve the original answer with the goal. If a decision sets a reusable rule, record the rule, scope, and source in Knowledge. Send a progress FYI only when requested. Record completion separately from approval to expand a rollout or experiment.

End a bounded review with the evidence, decision, and any open follow-up. For ongoing upkeep, improve this process by staging a narrow SOP edit, checking it against a later review, and retaining the decision source. When publishing team guidance, export reusable instructions and fictional examples through the repository's review process.
